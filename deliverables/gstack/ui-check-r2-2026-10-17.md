### ⚠️ WebKit 结论的局限（必须如实标注）

WebKit 在本次 Windows 环境下**无法验证**，原因是工具链而非站点：

- 全部 7 个资源请求（`style.css`、`fonts.css`、两个 woff2、`manifest.json` 等）均报 `SSL connect error`
- 失败请求的 URL 显示为 **`https://127.0.0.1:3001/...`** —— WebKit 构建把 HTTP 强制升级为 HTTPS，而本地服务不支持 TLS
- 改用 `http://localhost:3001` 结果相同
- 因此 WebKit 行的「暗色生效 7/7」是**假阳性**：body 背景为透明 `rgba(0,0,0,0)`，亮度算出 0，被判定为暗色

**替代验证**：Windows 上无法运行真 Safari，故 Safari 兼容性**未实测**，只能通过「未使用 Safari 不支持的 CSS 特性」做静态推断。此项列入已知局限，不作为通过结论。

### 修复过程中发现的两个环境级问题

| # | 问题 | 现象 | 处理 |
|---|---|---|---|
| 1 | **HSTS 在 HTTP 响应中下发** | helmet 默认对 HTTP 也发 `Strict-Transport-Security`，WebKit 据此把后续请求升级为 HTTPS，本地开发全部资源加载失败 | 已修：`hsts` 改为仅 `NODE_ENV=production` 启用（`d00f519`） |
| 2 | **Firefox 的 `colorScheme` 模拟不生效** | Playwright 设 `colorScheme:'dark'` 后 `matchMedia('(prefers-color-scheme: dark)')` 仍返回 false，误判为「Firefox 暗色不支持」 | 已改用 `firefoxUserPrefs: { 'layout.css.prefers-color-scheme.content-override': 0 }`，实测暗色完全正常 |

> 第 2 条尤其重要：若不做二次验证，会把「测试工具限制」误报成「Firefox 兼容性缺陷」。
